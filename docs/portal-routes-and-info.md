# Портал дизайн-системы: дерево роутов и структура информации

Документ задаёт **URL Next.js (App Router)** и **какую информацию** в каждом разделе держит портал как единый источник правды. Имена в URL — на английском (при необходимости позже добавляется локаль `/<locale>/...`).

---

## Дерево роутов

```
/                               Лендинг: быстрый вход, поиск, что нового, ссылки на Figma / Storybook / npm
/getting-started                Установка, зависимости, тема, первый пример

/components                     Каталог компонентов
/components/[slug]              Карточка компонента

/icons                          Иконки: набор, правила размеров и использования
/icons/[slug]                   Детальная страница набора или категории (по необходимости)

/colors                         Цвета: палитра, семантические роли (или фильтр токенов группы color)
/tokens                         Токены: группы (color, space, typography, radius, …)
/tokens/[group]                 Список токенов в группе (альтернатива: один /tokens с фильтром ?group=)

/guides                         Путеводитель / статьи: процессы, для кого что читать
/guides/[slug]                  Одна статья путеводителя

/changelog                      История изменений (кратко)
/releases                       Релизы пакета и портала; breaking changes, миграции
/releases/[version]             Одна версия (опционально)

/assets                         Assets: логотипы, шрифты, плагины, выгрузки для дизайнеров
/assets/[category]              Подраздел по типу (logos, fonts, plugins, …) — опционально

/support                        Поддержка: кому писать, каналы, SLA вопросов по DS

/roadmap                        Путеводитель по дорожной карте: статусы, планы, deprecated

/search                         Поиск по порталу (?q=…)

/studio                         Sanity Studio (редактирование контента)
```

**Группы маршрутов в коде (рекомендация):** `(marketing)` для `/`, `(docs)` с общим сайдбаром для разделов документации — без влияния на URL.

## Структура информации по разделам

### С чего начать (`/getting-started`)

- Установка пакета(ов), peer dependencies.
- Минимальный пример подключения (провайдер, стили).
- Версионирование и совместимость с продуктами.
- Ссылки: репозиторий, общий Storybook, общий файл Figma (library).

### Компоненты (`/components`, `/components/[slug]`)

- Имя, slug URL, статус (stable / experimental / deprecated).
- Краткое описание и подробное (поведение, варианты, a11y, keyboard).
- **Ссылки:** документация (внутренние страницы и внешние при необходимости), **Figma** (deep link), **Storybook** (story), исходники в Git.
- Превью / скриншоты из CMS (Media).

### Иконки (`/icons`)

- Перечень наборов или категорий; правила размера, stroke, отступов.
- Связь с кодом (импорт, пакет) и с Figma (библиотека иконок).
- Ссылка на Storybook (раздел иконок), если есть.

### Цвета (`/colors`)

- Семантические роли (`background.primary`, `text.default`) и/или сырьевая палитра.
- Связь с **токенами** группы `color`; при необходимости отдельные пояснения для дизайнеров vs разработчиков.
- Ссылка на страницу variables / styles в Figma.

### Токены (`/tokens`, `/tokens/[group]`)

- Группы: color, space, typography, radius, elevation, motion, …
- Имя в коде (`css variable` / имя токена), описание, опционально значение или отсылка «источник правды в коде @… v…».
- Фильтры и переключатель темы (light/dark), если актуально.

### Ссылки на документацию

- **Внутри портала:** все перечисленные роуты — основная документация.
- **Внешние:** Confluence, Notion, ADR — как поля «Дополнительные материалы» у компонентов/гайдов или блок на главной / в `/getting-started`.

### Ссылка на Figma

- **Глобально:** в шапке/футере (`/`, layout docs) — корневая библиотека или организация.
- **Точечно:** на странице компонента/токена — deep link на конкретный узел или variables.

### Ссылка на Storybook

- **Глобально:** базовый URL Storybook дизайн-системы.
- **Точечно:** URL story для компонента или раздела (иконки, паттерны).

### Changelog / Releases (`/changelog`, `/releases`)

- Хронология изменений; для релизов — версия npm, дата, breaking changes, ссылки на миграции.
- Связь версии портала и версии UI-kit (если разные репозитории).

### Assets (`/assets`)

- Логотипы (варианты, светлая/тёмная тема), шрифты, готовые архивы.
- Плагины (Figma, IDE) — описание, версия, ссылка на установку.
- Всё с версионированием и лицензией при необходимости.

### Поддержка (`/support`)

- Кому писать (роли, команда DS), каналы (Slack/Teams), типовые темы вопросов.
- Опционально: форма или mailto, часы ответа.

### Путеводитель и Roadmap (`/guides`, `/roadmap`)

- **`/guides`** — методические статьи: как пользоваться порталом, процессы внедрения, для какой роли какой раздел.
- **`/roadmap`** — отдельная страница дорожной карты: что в работе, что запланировано, что снято с поддержки; связь со статусами компонентов.

### Поиск (`/search`)

- Полнотекстовый или индекс по страницам компонентов, токенов, гайдов; параметр `?q=`.
- Удобно шарить ссылку на выдачу.

## Примечание для CMS (Sanity)

Схемы документов в Sanity должны отражать эти сущности (компоненты, токены, релизы, assets, гайды, глобальные URL Figma/Storybook). Роуты Next.js только **отображают** те же данные в нужной навигации.
