# Нейминг полей Payload CMS

## Имена полей (`name`)

Все **data fields** (поля с данными) требуют свойства `name`. Это ключ, по которому значение поля **сохраняется и читается из базы**. Имя должно быть **уникальным среди полей на том же уровне** (среди sibling-полей).

Пример:

```ts
export const MyField: Field = {
  type: 'text',
  name: 'myField',
}
```

---

## Конвенции именования

Имена полей напрямую становятся:
- ключами в объектах API-ответов;
- именами колонок в базе данных.

Поэтому они должны следовать **правилам идентификаторов JavaScript**:
- начинаться с **буквы** или **`_`**;
- содержать только **буквы, цифры** и **`_`**;
- по смыслу — как **имя переменной в JS** (на практике обычно **camelCase**: `sortOrder`, `storybookUrl`).

---

## Чего избегать

**Не используйте имена, которые:**
- начинаются с **цифры** (например `'1'`, `'2field'`);
- содержат **дефисы** (например `'field-name'`).

Хотя такие строки допустимы в TypeScript, они могут вызывать проблемы, когда Payload:
- обращается к данным через **dot-notation** (`doc.field-name` ломается);
- генерирует **GraphQL-схему**;
- маппит поля на **колонки БД**.

В GraphQL идентификаторы **не могут содержать дефисы** — поля с дефисом в имени приведут к ошибке генерации схемы.

---

## Зарезервированные имена

Payload резервирует некоторые имена для внутреннего использования. Если использовать зарезервированное имя, поле будет **удалено из конфига** (sanitized).

**Запрещённые имена:**
- `__v`
- `salt`
- `hash`
- `file`
- `status` — при адаптере **Postgres** и включённых **drafts** (черновиках)

Дополнительно (из более новых версий / migration guide): не рекомендуется использовать имена с префиксом **`_`** — такие имена зарезервированы под внутренние колонки и могут конфликтовать в SQL и других контекстах.

## Имена блоков (`blocks`)

У каждого блока есть **`slug`** — идентификатор типа блока. В данных он сохраняется как **`blockType`** и равен именно этому `slug`.

Поля **внутри блока** подчиняются тем же правилам, что и обычные поля (`name` в camelCase, без дефисов).

Связанные служебные свойства:
- **`blockType`** — slug блока (не заголовок в UI);
- **`blockName`** — опциональная подпись конкретного экземпляра блока в админке;
- **`block.label`** — общая метка типа блока (из `label` в конфиге или fallback на `slug`).

---

## Slug коллекции и global (для контекста)

Это не `name` поля, но часто путают:

- **`slug` коллекции / global** — уникальная URL-friendly строка-идентификатор (`posts`, `glossary-terms`, `portal-seo`);
- обычно **kebab-case** (строчные буквы, дефисы);
- из slug автогенерируются labels, имена таблиц, GraphQL-типы (если не заданы явно).

---

## Краткая шпаргалка

| Сущность | Свойство | Стиль | Пример |
|----------|----------|--------|--------|
| Поле | `name` | camelCase, без дефисов | `figmaUrl`, `sortOrder` |
| Коллекция / Global | `slug` | kebab-case | `brand-pages`, `portal-seo` |
| Блок | `slug` | часто camelCase | `codeExample`, `propsTable` |
| Запрещено для `name` | — | — | `__v`, `salt`, `hash`, `file`, `status`* |

\* `status` — только Postgres + drafts.
